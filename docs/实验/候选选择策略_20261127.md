# 候选前沿选择策略评测（2026-11-27）

> 执行底座：`platform/go2` 分支的 `demo_scan_stack.launch.py`（vkernel 虚拟设备 + mock robot + SCAN + PCT + BT）；下文 `src/` 路径均指该分支。
> 复现脚本：`experiments/frontier_policy/`；原始逐局结果：`experiments/frontier_policy/results/`。

## 0. 两个前提必须写清

1. **本仓没有 Gazebo**：`main` 与 `platform/go2` 对 `gazebo` 的引用为 0；仓库自带的仿真是 `vkernel_sim.py`（按参数化墙体合成雷达点云 + 里程计积分）。因此"固定地图 + 固定起点"用 vkernel 的 `walls / start_*` 参数实现，**不是 Gazebo 物理仿真**。
2. **原实现的前沿候选是桩**：`export_frontiers_from_keyframes()` 在无关键帧时退回 8 条 3–5 m 射线样本，常落在墙外。实测 smoke：选中 `ray_00 (5,0)`（5×5 房间外）→ `pct_path_failed`×6 → escape → 任务失败。信息增益、语义先验、SPL 评估在本仓原本都不存在，本次先补齐再测。

## 1. 实验协议

- 地图：10 m × 10 m、2×2 房间、门洞 1.2 m（`experiments/frontier_policy/map_rooms.yaml`），起点固定 `(1.5, 1.5, yaw 0)`。
- 目标：20 个点分布在 A/B/C/D 四室（A 为起始房）。
- 每局：武装 `SEARCH_SEMANTIC_TARGET` → 按策略选 frontier → PCT/SCAN 规划执行 → 到达后重选；预算 90 s / 8 次派发。
- 规模：4 策略 × 20 目标 = 80 局；消融 3 组 × 20 = 60 局；共 140 局，8 路并行（`ROS_DOMAIN_ID` 70–77 隔离）。
- 指标口径：
  - 成功率：任意时刻进入目标 **1.0 m** 内（ObjectNav 惯例）。
  - SPL：成功局 `L / max(P, L)` 的均值；L 为地图真值 A\* 最短路，P 为到首次到达的实际里程。
  - 决策耗时：`select_by_strategy()` 单次墙钟 P50/P95。
  - 行为切换：每局 BT `phase` 变化次数。
  - 无效重规划率：派发后出现 `pct_path_failed / replan_timeout / plan_fail_hold` 的派发占比。

## 2. 对比表（每策略 n=20，方括号为 Wilson 95% CI）

| 策略 | 成功率 | SPL | 决策 P50 | 决策 P95 | 行为切换/局 | 无效重规划率 | 决策次数 | 里程 |
|---|---|---|---|---|---|---|---|---|
| nearest（最近 frontier） | 20%（4/20）[8–42%] | 0.108 | 0.082 ms | 0.222 ms | 20.6 | 0.8% | 129 | 13.8 m |
| infogain（信息增益） | 35%（7/20）[18–57%] | 0.234 | 0.111 ms | 0.236 ms | 13.6 | 0.0% | 89 | 23.3 m |
| semantic（语义先验） | **75%**（15/20）[53–89%] | **0.692** | 0.115 ms | 0.214 ms | **10.8** | 4.8% | **62** | **7.9 m** |
| weighted（规则加权） | 60%（12/20）[39–78%] | 0.516 | 0.116 ms | 0.262 ms | 14.1 | 2.2% | 89 | 11.0 m |

分房间成功率（A/B/C/D）：nearest 0.6 / 0.0 / 0.2 / 0.0；infogain 0.4 / 0.0 / 0.4 / 0.6；semantic 0.6 / 0.6 / 1.0 / 0.8；weighted 0.6 / 0.6 / 0.6 / 0.6。
“成功时用了几次决策”均值：nearest 5.0、infogain 3.4、semantic 2.6、weighted 3.3。

## 3. 消融（weighted = 0.35·近距 + 0.35·信息增益 + 0.30·语义先验，去项后重归一）

| 配置 | 成功率 | SPL | 切换/局 | 无效重规划率 |
|---|---|---|---|---|
| weighted（全项） | 60% | 0.516 | 14.1 | 2.2% |
| − 距离项 | 75% | 0.674 | 12.3 | 0.0% |
| − 信息增益项 | **80%** | **0.683** | **12.1** | 2.7% |
| − 语义先验项 | **30%** | **0.281** | **19.5** | 3.3% |

## 4. 结论

1. **语义先验是唯一主导项**：去掉后成功率 60%→30%、SPL 0.52→0.28、切换 14→19.5，退化到 nearest 水平。带先验时 62 次决策 / 7.9 m 完成 15/20；nearest 用 129 次决策 / 13.8 m 只完成 4/20。
2. **距离项在本任务里有害**：0.35 的近距权重让机器人反复在近处小 frontier 打转（切换 20.6、决策 129 全场最高，成功率最低），去掉后升到 75%。
3. **纯信息增益“勤劳但盲目”**：里程最多（23.3 m）、无效重规划 0，但成功率 35%，B 房间 0 成功——unknown 占比最高的 frontier 多在传感器量程边界，把机器人拽着绕圈。
4. **决策耗时差异可忽略**（P50 0.08–0.12 ms、P95 0.21–0.26 ms），策略差距来自“选得对不对”，不是“算得快不快”。信息增益的建图/提取开销摊在 2 Hz 快照里，实测 `_grid_frontiers` 1.8 ms/次。
5. 无效重规划率整体很低（0–4.8%）；semantic 最高（4.8%）：更愿意往门洞/未知边界派发，撞规划上限略多，但收益远大于代价。

## 5. 局限

- 单 seed、每格 20 局，CI 很宽（semantic 53–89%），只能看趋势；
- 成功判据是“进入 1.0 m”，不是“到点停靠”；
- 决策耗时在 8 路并发下测得，属上界；
- 仿真底座为 vkernel（无 Gazebo），无接触/打滑物理。
