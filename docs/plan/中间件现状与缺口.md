# 中间件现状与缺口

本文按“已有 / 已设计未实现 / 缺失”记录中间件现状、边界与下一步缺口。

## 1. 核心问题

机器人在弱网/断网、定位可能失效、地图会切换的真实楼宇里，需要判断一条任务和一份空间状态“现在能否继续使用”，失效后如何恢复，以及如何保留可复用的执行经验。具体分为三个问题：

- 任务在正确的权限、时间、空间版本、通信条件下执行，结果可追溯（目标 1）；
- 状态不可信时按可信度分级恢复，而不是无差别重试（目标 2）；
- 经历转成可复用、可淘汰的经验（目标 3）。

它**不**解决：SLAM 精度、运动控制、通信传输本身。

## 2. 当前机制

已实现（PR #7）：统一的身份/版本/代数/坐标系（`AssetRef`）、增量基线校验（`DeltaRef.dispose`）、分级授权的可信度（`LocalizationHealth → Full/Restricted/Suspended/Revoked`）、唯一原因码、代数切换批量失效（TTL 未到期也可作废）。

已实现（PR #8）：执行租约（owner/epoch 栅栏与时效）、启动截止与运行超时分离、幂等判决、上行数据分类、恢复结果、Token 来源与验证状态、定位重置与地图代数切换的区分。Thin Harness 运行时接入、跨仓库适配器、JSON schema/IDL 生成和传输调度仍待实现。

机制的共同点：**所有判断都是契约里的纯函数**（`admit / dispose`），准入和运行期复用同一份，不让 BT 节点各写一套。

## 3. 接口对齐状态

当前已完成契约字段和代码映射的对齐，跨仓库运行期接入尚未完成。

- 端侧：Go2 的 `NavigationContextState`（generation/floor/map/session/frame）、`/lio/*` 话题、LNR 的 `RecoveryState` 到契约的映射表已写在 `docs/contracts/spatial_state.md`；适配器（C 阶段）未写。
- 边侧：DJI 物模型三要素 → Asset/Health/State、Intent/Query/Configure、Feedback/环境事件/安全事件的映射已定；`intent.v1` 九字段已定；JSON schema 和 IDL 生成未做。
- `localization_epoch` 与 `generation` 已分开定义；后续重点是完成端侧 SHM、适配器与运行期判决的一致接入。

## 4. 与现有中间件的边界

`Runtime + Harness + 记忆` 属于组合架构；ROS 2/DDS、Nav2、MoveIt 已覆盖通信、导航恢复与规划能力，本项目不替代这些组件。

差异化在三处别人没做或没做实的地方：

- **空间状态的"可用性语义"**：revision≠作废、generation=作废、localization_epoch 只作废位姿锚定、增量基线不符不应用——现有 OS 只有 TTL 和时间戳，没有这套代数/基线规则；
- **可信度驱动的分级授权 + 恢复后验证**，而不是置信分数或重试次数；
- **断网仍自主**：契约默认链路不可靠，运行时不依赖远端作为安全闭环的一部分；

真正的工程价值取决于**真机数据与基线数字**：在真实楼宇跨楼层场景下，证明这套语义比“TTL + 重试 N 次”降低错误经验复用率和恢复时间。该项当前尚无实测数据，由 C/E 阶段补齐。

## 5. 性能与长期稳定性

**目前没有证据。** 已有的只是 4 个单元测试、毫秒级跑完。长期稳定需要但尚无：长时间运行的内存增长曲线（TokenStore 淘汰、经验库上限）、DDS/SHM 压测（时延 P99、抖动、分配）、断链/重连循环的一致性、真机 MTBF。路线 M6/M7 列了这些指标，没一个有数字。诚实的说法：架构上为长期运行留了位置（代数失效、增量续传、本地日志），但"稳定"要靠 F 阶段压测和真机长跑证明。

## 6. 长期维护与版本兼容

**当前不具备 LTS 条件。** 现状：无版本号策略、无弃用流程、无兼容性承诺、无发布节奏。契约层已经预留 `schema_version`、`vocab_version`、`codec_id`，这是 LTS 的前提，但目前仅有字段。要建立长期版本维护，至少需要：契约语义化版本、同步更新映射表与测试、IDL 向后兼容规则、固定真机回放基线和冻结期。这些工作属于 F 阶段之后。

## 7. 系统级维护措施

现有基础：原因码统一（可审计）、证据链字段（可追溯）、本地 fragment log、CI 双平台、故障注入框架 v1。当前缺口：健康监控与告警、完整的跨仓库故障注入、配置/策略版本回滚入口、日志与回放工具链、安全更新机制。故障注入与回放回归应作为 B/C 阶段的验收要求。

## 8. 多机协同扩展

`robot_id/session_id/owner_id/epoch` 已为多执行者和多控制方预留字段；Spatial Asset/Delta 可用于跨设备共享空间状态；执行令牌/租约可作为多机共享通道、电梯或工位时的仲裁原语。多机阶段仍需解决空间资源所有权、跨节点信任与审计、共享资源冲突处理等问题。当前不为这些方向增加实现，只保持两条契约纪律：标识符带 owner/scope，决策带原因码和依据版本。

## 9. 优先结论

问题定义和核心契约已有基础，接口层已完成字段对齐，但运行期对齐、真机数据、性能证据和长期维护机制尚未齐备。近期优先级为：真机/回放旁路数据 → 跨仓库故障注入与回归 → 性能压测 → 长期版本维护。
