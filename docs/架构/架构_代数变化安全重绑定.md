# 架构：代数变化后安全重绑定（Rebind）

> 版本：2026-11-22 · 设计文档（目标态，未实现）
> 定位：**GO2 端侧自主**。不再有「边端协同」：世界/符号/度量三空间收编为端侧内部三层，
> 世界=端侧 VLM/世界模型，符号=技能运行时与契约，度量=执行内核。
> 信息流转：两平面（符号 ↔ 度量）全部经 **DDS（发现/控制/生命周期/反馈）+ SHM（同机零拷贝）
> + UDP（跨机分片，按需）**，QoS 分级，实现侧 **C++**，强调**信息实时性与生命周期状态**。
> 通信基线：CycloneDDS 0.10.5 + iceoryx 2.0.5 + Humble + Domain 0，**不升级**；本设计新增的消息
> 是既有链路的**并集**，不修改既有类型、不换 Domain。

---

## 1. 背景与问题

当前已实现「代数变化则失效」的框架（StateGate / ContractGate / context_generation /
data-layer stale），但缺少「代数变化后如何安全重绑定」：系统只能安全停下，不能在新代上
受控继续。本文补齐四件事，使「失效」升级为「可安全重绑定」。

## 2. 四件事

1. **统一 WorldRef / version vector**：单一世界引用身份。
2. **rebind 状态机 + 幂等事务**：旧代 → 新代的受控交接。
3. **派生件代际标签**：path/traj/token/subgraph/lease 统一携带 generation。
4. **old→new 可审计反馈链**：rebind 事件留痕。

## 3. 核心对象（接口用 .msg，不用 schema/JSON）

见同目录 `msg-*.msg`（实为 `src/motionslam_msgs/msg/*.msg`）：

| 类型 | 作用 |
|---|---|
| `WorldRef.msg` | 统一版本向量：asset_id/map_id/floor_id/tile_id/revision/context_generation/frame_id/digest |
| `TaskBinding.msg` | 任务在当前世界代数上的绑定：task_id + task_revision + bound_world_ref + lease_epoch + plan_id + traj_id |
| `RebindRequest.msg` | 重绑定事务请求：task_id + from/to WorldRef + reason + policy |
| `RebindRecord.msg` | old→new 审计记录：from/to + result + invalidated_artifacts + stamp |
| `RebindState.msg` | 任务级重绑定生命周期状态 |
| `ArtifactEpoch.msg` | 派生件代际标签：generation + stamp |

> 事务入口为纯 msg 形态（RebindRequest → RebindRecord.result 作为应答），不引入 srv。

## 4. rebind 状态机（幂等事务）

```text
BOUND ──代际失效──▶ INVALIDATED ──rebind(tid,from,to)──▶ REBIND_PENDING
                                                        │ 校验 from == 当前绑定
                                                        │ 校验 to 资产可解析/差分可接受
                                                        ▼
                                          ┌─ 通过 ─▶ REBIND_READY ─▶ RESUMED
                                          └─ 拒绝 ─▶ REBIND_REJECTED ─▶ FAILED / WAIT
```

- **幂等键**：`(task_id, from_world_ref, to_world_ref)`；重复提交返回已存在结果，不重复执行。
- **安全语义**：
  - REBIND_PENDING 期间，旧代派生件（path/traj/token/subgraph/lease）全部 `invalidate(generation)`；
  - 新 lease 重新签发；
  - 所有安全源（estop/recovery/contract/terrain）Normal 后才允许 RESUMED；
  - 任何一步失败 fail-closed 到 REBIND_REJECTED。
- **可审计反馈链**：`rebind_requested → validated → applied / rejected`，每条带 from/to 两代 +
  invalidated_artifacts。

## 5. 派生件代际标签

| 派生件 | 标签载体 | 失效语义 |
|---|---|---|
| `/global_path` | ArtifactEpoch.generation | 与任务绑定 generation 不符 → 拒收 |
| `/initial_path` | 同上 | 同上 |
| `/planning/bspline` + `traj_id` | 同上 + traj_id 单调 | 旧 traj_id 作废 |
| Token / 子图（MSTOK / sparse_subgraph） | `context_generation` | 旧代不消费 |
| lease（执行租约） | lease_epoch | 新 state 上重签 |

## 6. DDS 承载与 QoS（强调实时性 / 生命周期）

| 主题 | 承载 | QoS |
|---|---|---|
| `symbolic/world_ref` | WorldRef 资产目录/版本 | RELIABLE + TRANSIENT_LOCAL |
| `symbolic/task_binding` | TaskBinding + RebindState | RELIABLE |
| `symbolic/rebind` | RebindRequest | RELIABLE |
| `exec/rebind_record` | RebindRecord 审计链 | RELIABLE |
| 度量热链 `/planning/bspline`、`/motion/command` | 实时运动原语 | BEST_EFFORT + 小 depth |
| 大载荷 cloud/map/token | SHM（motionslam_ipc 环） | 同机零拷贝；跨机 UDP 分片 |

约束：Domain 保持 0；新 topic 不撞机身既有 `rt/` 命名；新类型为并集，不改 `RuntimeEnvelope`
等既有类型字段；`libddsc/iceoryx/Humble` 版本不动。

## 7. 与现有代码的映射与差距

| 设计件 | 现有锚点 | 差距 |
|---|---|---|
| WorldRef | `runtime/task_runtime` WorldReference、`runtime_core` TaskIntent.world_ref | 字段不一致，需统一 + 加 digest |
| 代际失效 | StateGate、ContractGate、data_layer_types | 只「失效」不「重绑定」 |
| 派生件代际 | MapSessionManager.generation、LoopDetectionNode.context_generation | path/traj/token/subgraph 无统一 generation 标签 |
| 审计链 | TaskRuntime.events_、ExecutionFeedback | 无 from/to 两代与 rebind 事件 |

实现归属：**rebind 状态机 → runtime/task_runtime（C++ 生命周期权威）**；**WorldRef 校验 →
runtime_core（C++ 契约权威）**；**消息 → motionslam_msgs**；**SHM 代际沿用 motionslam_ipc 的
generation 语义**。

## 8. 实施顺序与门禁

1. 设计文档 + 接口草案（本文件 + msg，先出）。
2. runtime/task_runtime（C++）：rebind 状态机 + 幂等事务 + 安全源仲裁。
3. runtime_core（C++）：统一 WorldRef 校验 + 派生件代际标签接入。
4. motionslam_msgs：msg 注册 + 类型生成（`--check` 同步）。
5. motionslam_bringup：BT 侧 revalidate_goal + old→new 审计链上行。
6. 门禁：契约测试 + `gen_dds_types.py --check` 同步；真机前 vkernel 仿真联调。

## 9. 已知缺口（随本设计一并治理，不在本阶段单独修 forwarder）

- `traj_id/sequence` 端到端校验、ExecStatus 回执、看门狗统一时钟源、slow-mode 异步改参、
  地形 HOLD 与 BT 恢复计时分叉 —— 执行边界以 BT 为准，不修 CmdVelForwarder。
- 度量层单元测试不单独补测，随 vkernel 仿真联调统一验收（写入开发计划）。
