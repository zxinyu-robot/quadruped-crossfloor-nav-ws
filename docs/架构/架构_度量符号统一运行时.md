# 度量—符号统一运行时（主链接入）

> 状态：2026-11-27 · 代码已接主链（`with_runtime_bridge:=true`），仿真验证通过；真机未接。
> 上游约束见 [端侧系统架构](架构_端侧系统架构.md) 与 [符号空间契约](../符号空间契约.md)。

## 1. 为什么要"统一"，而不是两套并跑

现状是两条腿：度量平面（`src/`：LIO → PCT → SCAN → BT → cmd_vel）已经在真机主链跑；
符号平面（`runtime_core/`：语义观测 → TaskIntent 准入 → 技能编排 → 执行反馈）在测试里闭环，
但**BT 的搜索/导航入口仍可被直接 `task_accepted` 事件驱动，绕过任何裁决**。
本次实验也暴露了同一件事：候选前沿由 `subgraph_publisher` 直供 BT，缺置信度/有效期，
BT 拿到过期或不可执行候选就派发（`search_exhausted: no_frontier` / `plan_fail_*`）。

统一的原则只有一条：**上游只能表达"要做什么"（TaskIntent），端侧独占"能不能做/怎么做"**。
语义只影响偏好，不构成几何可执行许可；度量层（规划/安全）对语义结论有一票否决。

## 2. 统一模型

```
世界空间(模型/边/云)            端侧统一运行时                        度量执行
   TaskIntent  ──►  RuntimeBridge ──► TaskGate(L1..L5) ──► 技能(BT 子树) ──► PCT/SCAN/控制
        ▲                                     │                                   │
        └────────── ExecutionFeedback ◄───────┴──── /runtime/gate 裁决事件 ◄────────┘
```

一次裁决消费的**唯一状态对象**（`SpatialTaskState`）由四部分组成，缺一即不可执行：

| 组成 | 字段 | 来源 | 失效语义 |
|---|---|---|---|
| 符号意图 | `skills[]`, `priority`, `deadline`, `revision` | TaskIntent | 技能不在白名单 → 拒绝 |
| 度量锚点 | `x,y,z,yaw`, `map_id`, `revision` | LIO/BT | 地图/代数不一致 → 拒绝 |
| 有效性 | `localization_confidence`, `timestamp_ns`, `valid` | LIO 新鲜度 + PGO + 漂移 | 过期/低置信 → 降级停站 |
| 执行上下文 | `candidate_count`, `forbidden_areas` | 快照/本地配置 | 无候选 → 降级；入禁区 → 拒绝 |

## 3. 五级校验（唯一裁决面）

实现：`runtime_core/src/legged_nav/task_gate.py`（编排）+ `task_intent.py`（契约/禁区）+
`spatial_state.py`（有效期/置信度）+ `admission.py`（幂等/抢占）。
C++ 权威镜像（`task_intent` / `spatial_state` / `admission`）已在仓；**Gate 组合层目前只有 Python 实现**（见 §8）。

| 级别 | 检查 | 失败结果 | 对应约束 |
|---|---|---|---|
| L1 契约与技能白名单 | schema、平台/机器人、技能 ∈ 白名单、无 `cmd_vel/twist` 等控制字段 | `REJECT` + `REJECT_*` | C6 |
| L2 参数有界 | 目标有限、在地图边界内、距本体 ≤ `max_goal_dist_m`、deadline/priority 范围 | `REJECT` | C6 |
| L3 状态有效性 | 置信度 ≥ 阈值、`now - stamp ≤ ttl`、地图/代数一致 | `DEGRADED(stop_and_hold)` | C1a / C13 |
| L4 度量可行性 | `ExploreFrontier` 需要 `candidate_count > 0` | `DEGRADED(no_candidate)` | C12 |
| L5 安全约束 | 意图点名禁区 fail-closed；本地禁行区无论点名与否一律拒 | `REJECT` | C13 |
| 仲裁 | task_id 幂等 / 优先级抢占 / 忙拒 | `ACCEPT(IDEMPOTENT)` / `REJECT_BUSY` | C12 |

裁决只返回三种结果，BT 侧的解释口径固定（`degrade_policy()`）：

- `ACCEPT` → `run`
- `DEGRADED` → `hold_in_place`（L3/L4）；`geometric_only`（语义先验缺失时的策略层降级）
- `REJECT` → `reject`

## 4. 主链接线

| 项 | 值 |
|---|---|
| 启动 | `ros2 launch motionslam_bringup demo_scan_stack.launch.py with_runtime_bridge:=true runtime_gate_mode:=enforce` |
| 上游入口 | `/runtime/task_request`（`std_msgs/String`，TaskIntent JSON；`robot.platform` 用契约值 `unitree_go2`） |
| 裁决可观测 | `/runtime/gate`（决策/级别/码/降级模式/候选数/PGO/漂移/odom 龄期） |
| 下行 | 通过则发 `task_accepted`（带 `gate: runtime` 与 `stage_ids`）到 BT；否则 `task_rejected` |
| 语义有效性 | 裁决结果同步到 `/semantic/valid`，下游据此关闭语义通道 |
| 影子模式 | `runtime_gate_mode:=shadow` 只观测直接进入 BT 的 `task_accepted` 并输出裁决，不改行为，用于灰度 |

**enforce 的前提**：所有生产者改发 `/runtime/task_request`。仓内 `command_executor` / 边端 mock
仍直发 `/demo/mission/event`，接真机前必须切过去（否则 equal 于绕过闸门）。

## 6. 降级矩阵

| 触发 | 判定 | BT 动作 | 用户可见 |
|---|---|---|---|
| odom 过期 / 置信度低 | L3 `SAFETY_INTERLOCK:*` | `hold_in_place` | `task_rejected` + `runtime_degraded` |
| 搜索无有效候选 | L4 `REJECT_NO_CANDIDATE` | `hold_in_place`，等新一轮快照 | 同上 |
| 候选全部过期（`candidate_gated`） | 搜索预算内重试 | 重试；仍无则 `search_exhausted: no_valid_frontier` | 任务失败原因可读 |
| 语义先验缺失（断网） | 策略层 `geometric_only` | 退回几何/信息增益探索 | 成功率下降但不停机（实测 75%→30%） |
| 目标入禁区 | L5 | `reject` | `task_rejected` + 区域 ID |

## 7. 可观测性与评测口径

`/runtime/gate` 每次裁决一行 JSON；建议按会话聚合：
`accept_rate`、`reject_rate_by_code`、`degraded_seconds`、`candidate_dropped/kept`、`odom_age_ms` P95。
候选门控指标已并入搜索事件（`candidate_gated`、`frontier_selected.candidate_dropped`）。

## 8. 已验证 / 未验证

**已验证**
- `runtime_core` 新增 `TaskGate` 11 项单测通过（L1–L5 顺序、降级模式、仲裁、禁区 fail-closed）。
- 桥在云仿真主链上跑通：`Fly` → L1 `REJECT_SKILL_UNSUPPORTED:Fly`；`ExploreFrontier` 无候选 → L4 `DEGRADED(no_candidate)`
  + `runtime_degraded`；`Navigate` → `ACCEPT(level 6)` 并下发 `task_accepted(gate=runtime)`
  （`/runtime/gate` 记录完整裁决：`{"decision":"ACCEPT","level":6,"code":"accept",...}`）。

**未验证**
- C++ `TaskGate` 组合层未实现（现有 C++ 只有 `TaskAdmission` / `StateGate` / `validate_task_intent` 三个零件），
  因此主链目前依赖 Python 实现；补齐后用同一组用例做双实现对照。
- 真机主链未接（`command_executor` / 边端仍直发 BT 事件）。
- 语义先验的"置信度"仍是启发式（odom 龄期 + PGO 状态 + 漂移惩罚），未与 LIO 协方差直接挂钩。

## 9. 复现

```bash
# 单测
cd runtime_core && PYTHONPATH=src python3 -m pytest -q tests/test_task_gate.py

# 主链冒烟：bad skill / 无候选 / 正常导航
ros2 launch motionslam_bringup demo_scan_stack.launch.py with_runtime_bridge:=true runtime_gate_mode:=enforce \
  with_sensors:=false with_lio:=false with_mock_robot:=true with_semantic_objnav:=true \
  vkernel_params_file:=<map.yaml> runtime_core_src:=<repo>/runtime_core/src
# 契约字段是嵌套的：robot.platform ∈ {unitree_go2, unitree_go2_edu}，robot.sn，world_ref.map_id/revision
cat > /tmp/intent.json <<'JSON'
{"schema":"motionslam.task_intent.v1","task_id":"t1",
 "robot":{"platform":"unitree_go2","sn":"go2-01"},
 "world_ref":{"map_id":"m1","revision":0,"frame_id":"world"},
 "skills":[{"name":"Navigate","goal":{"x":1.0,"y":1.0,"z":0.0}}]}
JSON
ros2 topic pub --once /runtime/task_request std_msgs/msg/String "{data: '$(cat /tmp/intent.json)'}"
ros2 topic echo /runtime/gate
```
