# 模块职责与交互契约（main）

> 本文是 `main` 上三个运行时模块的职责划分和跨模块接口的唯一说明。事实按 `main@ea88057` 的代码核对；
> 标「建议」「待定」的是还没落到代码里的决定。Go2 真机链路在 `platform/go2` 分支，本文只写它和运行时之间的接口。

## 1. 结论

- 三个模块各有一块别人没有的能力，但**任务状态机、空间状态、原因码各有两到三套**，互不引用。
- 建议的权威划分：**任务生命周期归 `runtime_core`，空间状态与原因码归 `fork_spatial`，插件与恢复仲裁从 `task_runtime` 并入 `runtime_core`**。
- 契约原件不搬家（搬了会打断 `gen_contract.py` 和 `git subtree pull`），统一由 [`contracts/README.md`](../../contracts/README.md) 索引。

## 2. 模块职责

| 模块 | 只管什么 | 不管什么 | 证据等级 |
|---|---|---|---|
| `runtime_core/` | 任务意图准入（schema / 平台 / 禁控字段 / 幂等 / 忙态 / 抢占）、`StateGate`、技能展开、`Forwarder` 抽象、执行反馈、DDS 类型生成 | 定位 / 规划 / 速度下发；空间状态的版本与代际 | 合成数据·单元测试 |
| `runtime/task_runtime/` | 另一套任务状态机（含 `paused`、`SafetyMode`）、`PluginRegistry`、LNR 恢复建议仲裁（`RecoveryArbiter`）、FSR 契约门（`ContractGate`） | 准入的 schema 校验、反馈编码 | 合成数据·单元测试 |
| `fork_spatial/` | 空间状态契约（`AssetRef` / `Stamp` / `LocalizationHealth` / `ExecutionAuthority` / `ExecutionLease` / `ReasonCode`）、故障注入、Token / ESN / 端侧策略、`MissionOrchestrator` 参考执行器 | 不向机器人下发运动；`MissionOrchestrator` 不再扩功能（见其 `docs/contracts/spatial_state.md`） | 合成数据·单元测试 |
| `interfaces/motionslam_msgs/` | 跨平面 `.msg` 原件；`RuntimeEnvelope` 只载符号量 | 不承载几何量或速度 | 草案（rebind 6 个）/ DDS 互通实验 |
| Go2 Robot Adapter（`platform/go2`） | 把运行时的技能步骤翻成 Go2 话题，回报位姿与结果 | 任务该不该接 | **未实现**；现状是编排器直接接任务 |

## 3. 重叠点对照

### 3.1 任务状态

| `runtime_core` `TaskStatus` | `task_runtime` `TaskStatus` | `fork_spatial` `MissionStatus` | `fork_spatial` `FeedbackStatus` |
|---|---|---|---|
| ACCEPTED | kAccepted | — | Accepted |
| — | — | Idle / WaitReady | — |
| RUNNING | kRunning | Running | Running |
| — | kPaused | — | — |
| HOLDING | kHolding | — | Blocked |
| — | — | Recovering | Recovering |
| SUCCEEDED / FAILED / CANCELED | kSucceeded / kFailed / kCanceled | Succeeded / Failed / Canceled | Succeeded / Failed / … |
| REJECTED | 由 `SubmitResult` 表达 | — | — |

建议：生命周期以 `runtime_core` 为准，补 `PAUSED`（显式暂停）与 `RECOVERING`（技能内恢复中，对外可见）；
`MissionStatus` 只在参考执行器内部使用，不进入跨模块接口。

### 3.2 任务意图

| | `runtime_core` `TaskIntent` | `task_runtime` `TaskIntent` |
|---|---|---|
| 身份 | `task_id`、`platform`、`robot_id` | `task_id`、`task_type` |
| 世界引用 | `map_id`、`floor_id` | `world_reference{asset_id, revision, context_generation, frame_id}` |
| 技能 | `skills[]{name, goal}`，技能名白名单来自 `runtime_contract.json` | `skill_sequence[]{skill, target}`，无白名单 |
| 执行策略 | 准入时的优先级 / 抢占 | `execution{priority, deadline_ns, preemptible}` |
| 校验 | schema、禁控字段、类型严格 | 仅非空与重复 |

建议：以 `runtime_core` 的 schema（`motionslam.task_intent.v1`）为准；把 `map_id`/`floor_id` 升级为
`fork_spatial` 的 `AssetRef`（补 `revision` 与 `context_generation`），版本号升到 `v2`。

### 3.3 空间状态

| | `runtime_core` `SpatialState` | `fork_spatial` 契约 |
|---|---|---|
| 身份 / 版本 | `map_id`、`revision` | `AssetRef{asset_id, revision, context_generation, frame_id, pose_anchored}` |
| 时间 | `timestamp_ns`（本地时钟） | `Stamp{…, clock: Monotonic / WallUtc}` |
| 可信度 | `localization_confidence`、`valid` | `LocalizationHealth{mode, quality, pose_jump_m, alignment_fitness, …}` → `ExecutionAuthority{Full, Restricted, Suspended, Revoked}` |
| 门控 | `StateGate(ttl=500 ms, min_confidence=0.5)` | `admit()` → Accept / Reverify / Hold / Reject；`ExecutionLease` 处置 |

建议：空间状态以 `fork_spatial` 为准；`StateGate` 改为消费 `AssetRef + Stamp + LocalizationHealth`，
TTL 与置信度阈值保留为 `StateGate` 参数。

### 3.4 失败原因

现有三套：`runtime_core` 反馈原因（`reached` / `stuck` / `plan_fail` / `link_lost` 等）与准入拒绝码（`REJECT_*`）、
`task_runtime` 的字符串 `reason`、`fork_spatial` 的 `ReasonCode`（`PlanFailed`、`Stuck`、`LocalizationLost`、`LeaseExpired`、`IdempotencyConflict` 等 20 个）。
`fork_spatial/docs/contracts/spatial_state.md` 已写明 `ReasonCode` 是「唯一一套」。

建议：执行期失败统一用 `ReasonCode`；准入拒绝码保留在 `runtime_core`（属于入口校验，不是执行失败），并给出到 `ReasonCode` 的映射表。

## 4. 跨模块接口（按工程规范 A8 的维度）

「—」表示当前代码没有定义，需要在合并时补上。

| 接口 | 数据 | 时空 | 生命周期 / 有效性 | 超时与取消 | 失败 / 执行权 | 兼容 |
|---|---|---|---|---|---|---|
| 世界侧 → 运行时：`TaskIntent` | `motionslam.task_intent.v1` JSON，禁控字段直接拒绝 | `map_id` / `floor_id`；无时钟 | task_id 终态后仍占用 | — | `REJECT_*`；运行时有准入权 | `schema` 字段带版本 |
| 定位 → `StateGate`：`SpatialState` | 位姿 + 置信度 + 地图版本 | 本地时钟 ns，坐标系未写 | TTL 500 ms、置信度 ≥ 0.5 | 过期即 HOLDING | 门控只拦不执行 | — |
| 运行时 → 平台：`Forwarder::execute(step, deadline_ns)` | `ActionStep{kind, goal}`，kind ∈ navigate_to / return_home / explore / stand / stop | goal 坐标系未写 | 每步一个 deadline | `abort(reason)` | `StepResult{ok, detail, final_state}`；**执行权在平台** | — |
| LNR → `RecoveryArbiter`：恢复建议 | `RecoveryInput` / `RecoveryAdvice` | `timestamp_ms` | 心跳超过 2 倍健康周期判 stale | stale → Hold | `PluginAuthority::kAdvice`：**只给建议**，仲裁器决定 | `interface_version` |
| FSR → `ContractGate`：空间状态 + 租约 | `admit()` 结果 + `LeaseDisposition` | `Stamp.clock` 必须一致 | 租约 `Expired` / `StaleEpoch` 等 | 租约过期 → Hold + fail | 只驱动 "contract" 安全源 | — |
| 运行时 → 世界侧：`ExecutionFeedback` | `motionslam.execution_feedback.v1` | — | — | — | 稳定原因码 | `schema` 字段带版本 |
| 跨进程信封：`RuntimeEnvelope.msg` | `schema_version` + `channel_id` + JSON payload | `stamp_ns` | — | — | 只载符号量 | `schema_version` |

## 5. 合并顺序（每步一个 PR）

1. 本文 + 契约索引（只改文档）。
2. 原因码统一：`runtime_core` 反馈改用 `fork_spatial` `ReasonCode`，加准入拒绝码映射表。
3. 空间状态统一：`StateGate` 改读 `fork_spatial` 契约类型；`TaskIntent` 升 `v2`。
4. `task_runtime` 的 `PluginRegistry` / `RecoveryArbiter` / `ContractGate` 并入 `runtime_core`，补 `PAUSED` / `RECOVERING`，然后删除 `runtime/task_runtime`。
5. Go2 Robot Adapter（实现 `Forwarder`，overlay 外原生进程）。

**待定**：HOLD 在 Go2 上只能用 cancel 实现（终止而非暂停），第 5 步前需要定取舍。

---
用词表：**准入**＝决定任务接不接；**门控**＝执行中判断空间状态还能不能用；**租约**＝带有效期的执行授权；**仲裁**＝在多个建议里决定听谁的。
