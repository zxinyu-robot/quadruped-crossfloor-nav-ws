## 1. 项目整体结构

仓库入口与主要目录：

- 根构建配置：[`CMakeLists.txt`](../CMakeLists.txt)
- 顶层说明：[`README.md`](../README.md)
- 架构说明：[`architecture.md`](architecture.md)
- 核心源码：[`src/`](../src/)
- 示例与测试：[`examples/cpp/`](../examples/cpp/)

核心库由 [`src/CMakeLists.txt`](../src/CMakeLists.txt) 组织为 4 个模块：

1. `contract`：跨系统空间状态契约与判决逻辑
2. `runtime`：图状态、事务提交、窗口推进、优化快照
3. `cognition`：Token 编码与存储、ESN 行为记忆、端侧策略管理
4. `mission`：任务编排器（子目标派发、恢复与终态）

## 4. 端到端调用链（时序梳理）

1. **观测输入 → Token 编码**
   - `GeometricObservation` 经 `RuleBasedTokenEncoder::encode()` 生成 Token。
2. **Token 入库与生命周期管理**
   - `TokenStore::upsert()` 校验 revision/时序/置信度；
   - `TokenStore::tick()` 周期推进 Token 生命周期。
3. **行为特征构建与记忆更新**
   - `make_behavior_input(tokens, feedback)` 形成固定输入向量；
   - `EchoStateMemory::update()` 产生时序状态 `x_t`。
4. **策略决策**
   - `EdgePolicyManager::decide(tokens, behavior_input, memory)` 产出决策；
   - 无 active 策略或记忆未 warmup 时走 `rule_fallback`。
5. **执行结果回流学习**
   - `report(outcome, features)` 更新 active 统计与 candidate 学习；
   - `try_promote()` 在验证通过后晋升候选策略。
6. **图状态提交与滑窗推进**
   - `SpatialRuntime::submit(batch)`：候选校验通过后原子提交；
   - `advance_window(watermark)`：边缘化先验 + 状态迁移原子提交；
   - `optimize()` 输出快照。
7. **任务编排闭环**
   - `MissionOrchestrator::tick(state, planner_ready)` 驱动状态机；
   - 规划失败/定位异常触发恢复阶梯；
   - `on_pose_corrected()` 处理纠偏后重派发。

## 5. 接口清单（输入 / 输出 / 失败码）

## 5.1 contract 接口

- `admit(header, expected, now)`  
  - 输入：`SpatialStateHeader`、期望 `AssetRef`、当前时间  
  - 输出：`AdmitResult`（Accept/Reverify/Hold/Reject）
- `dispose(lease, ...)`  
  - 输入：`ExecutionLease` + 当前执行上下文  
  - 输出：`LeaseDisposition`
- `dispose(delta, local)`  
  - 输入：`DeltaRef`、本地 `AssetRef`  
  - 输出：`DeltaDisposition`

常见拒绝原因：`AssetStale`、`StaleEpoch`、`Expired`、`DeadlineMissed`、`MissingDeltas`。

## 5.2 runtime 接口

- `submit(const FactorBatch&) -> SubmitResult`
- `advance_window(Timestamp) -> SubmitResult`
- `optimize() -> EstimateSnapshot`

`SubmitCode`：

- `Accepted`
- `DuplicateFactor`
- `InvalidState`
- `InvalidNoise`
- `LateObservation`
- `BackendRejected`

## 5.3 cognition 接口

- Token：
  - `TokenStore::upsert(SemanticToken) -> UpsertCode`
  - `TokenStore::tick(now) -> size_t`
- 记忆：
  - `make_behavior_input(tokens, feedback) -> vector<double>`
  - `EchoStateMemory::update(input) -> const vector<double>&`
- 策略：
  - `decide(tokens, behavior_input, memory) -> PolicyDecision`
  - `report(outcome, features) -> void`
  - `try_promote() -> bool`

## 5.4 mission 接口

- `submit(MissionRequest) -> bool`
- `tick(RobotState, planner_ready) -> MissionCommand`
- `cancel(reason) -> bool`
- `on_plan_failed() / on_planner_ready() / on_pose_corrected()`

终态：`Succeeded / Failed / Canceled`，失败语义与契约 `ReasonCode` 对齐。

## 6. 当前梳理结论（摘要）

- 项目已形成“契约门控 + 认知策略 + 状态事务 + 任务编排”的清晰分层。
- `runtime` 聚焦一致性边界，`contract` 提供跨系统统一判决语言。
- `cognition` 的策略路径与 `mission` 编排路径解耦，适配层可独立接入。
- 测试位于 `examples/cpp`，按模块划分明确，便于回归验证。

## 7. 数据流转时序图（Canvas）

已在 Canvas 绘制 **ForkSpatial 数据流转时序图（端到端）**，覆盖以下主链路：

1. 观测输入 / 状态上报 → `contract` 门控判决  
2. 几何观测 → Token 编码 → TokenStore 生命周期管理  
3. valid tokens + 执行反馈 → 行为输入 `u_t` → ESN 记忆 `x_t`  
4. `x_t + u_t` → 策略决策 → 执行层  
5. 执行结果回流 → 策略学习/候选晋升与回滚  
6. 执行层因子批次 → Runtime 事务提交 → 窗口推进与优化  
7. 执行层状态 + planner_ready → Mission 编排 → 任务命令回到执行层
